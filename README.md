# Dashboard FiveM (ex-GTASUN Staff Manager)

Dashboard **multi-serveurs** de gestion de serveurs FiveM : staff, grades, avertissements, activité (vocal Discord + temps de jeu), bilan IA hebdomadaire.
Un **serveur** du panel = un serveur Discord + (optionnellement) un serveur FiveM. Toutes les données sont rangées par serveur.

Trois dossiers indépendants :

| Dossier | Rôle | Hébergement |
|---|---|---|
| [`site/`](site) | Panel web (Next.js) + base libSQL (Turso en prod). Il possède **toutes les données**, rangées par serveur. | Vercel / un serveur Node |
| [`bot/`](bot) | **Un seul** bot Discord pour tous les serveurs. Il surveille les serveurs Discord enregistrés sur le site et **envoie tout au site par API**. Aucune base de données. | N'importe où (VPS, conteneur…), il suffit qu'il joigne le site |
| [`fivem/`](fivem) | Ressource `fiverax_agent` : relie chaque serveur FiveM au site (`/api/fivem/agent`) avec le **token propre à son serveur**. Joueurs en direct, carte & vocal, kick, messages, annonces, ressources, console, **anticheat**, **bans** et déploiement du **Studio IA**. | Chaque serveur FiveM |

## Comment ils se parlent
```
Discord (N serveurs) ──► bot ──(HTTPS, Bearer BOT_API_TOKEN, guildId dans chaque message)──► site ──► base
FiveM (1 par serveur) ──(HTTPS, Bearer <token du serveur>)────────────────────────────────► site
```
- Le bot demande au site la liste des serveurs Discord à surveiller (`POST /api/bot/servers`, toutes les 5 min) et ignore les autres.
- Chaque message du bot (`sync`, `member`, `voice`, `playtime`) indique son `guildId` ; le site le range dans le bon serveur. `heartbeat` liste les serveurs où le bot est présent, ce qui permet au panel d'afficher « bot absent » serveur par serveur.
- `tick` (10 min) : nettoyage des sessions FiveM, puis bilan IA du dimanche **de chaque serveur, dans son propre fuseau horaire**.
- Le token d'un agent FiveM désigne son serveur : un agent ne peut jamais écrire dans un autre serveur.
- L'agent FiveM **interroge** le site (toutes les 2 s quand quelqu'un regarde les pages « En direct », 8 s sinon) : il envoie connexions, déconnexions, console et résultats, et reçoit les actions en attente. Aucun port à ouvrir, compatible Vercel. Une action non récupérée en 2 min est abandonnée (jamais exécutée en retard). L'ancien endpoint `/api/fivem` (agent 1.x) marche toujours.
- `server.cfg` : `set fiverax_url "https://…"`, `set fiverax_token "fvm_…"`, `add_ace resource.fiverax_agent command allow`, `ensure fiverax_agent` (les lignes exactes sont données dans Configuration). `set fiverax_console 0` refuse la console depuis le panel, `set fiverax_deploy 0` les déploiements du Studio IA, `set fiverax_audit_code 0` l'envoi de code pour le scanner, `set fiverax_files 0` l'accès de l'assistant IA aux fichiers (`1` : lecture seule).
- `add_ace group.admin fiverax.bypass allow` : le staff n'est jamais contrôlé par l'anticheat. `ensure screenshot-basic` (facultatif) : captures d'écran analysées par l'IA. Un script qui téléporte un joueur peut appeler `exports.fiverax_agent:allowTeleport(source, secondes)`.

## Sécurité
- **Centre de sécurité** (Sécurité > Centre de sécurité, permission « Voir l'anticheat… ») : une note globale de A+ à F sur 100, en quatre piliers pondérés : le code (scan complet, 30 %, compte pour moitié après 30 jours), le jeu (couverture de l'anticheat quand l'agent tourne, 25 %), le Discord (anti-raid + audit des permissions, 25 %) et la réaction (alertes, sauvegardes, bans partagés, 20 %). Un pilier absent compte 0. On y voit l'état en direct (agent, bot, anticheat, anti-raid), l'activité des 7 derniers jours comparée aux 7 d'avant, les **joueurs à surveiller** (score de risque 0-100 : chaque détection pèse selon sa gravité, ×1,5 si confirmée, les captures jugées « cheat » par l'IA en plus, les faux positifs jamais), les recommandations prioritaires (niveau Fiverax suivant, audit Discord, réglages) et les derniers événements.
- **Anticheat 3.8** (agent `fiverax_agent` 3.8.0) : noclip (le ped avance plusieurs contrôles d'affilée sans vitesse réelle synchronisée, jamais compté pour une téléportation de script, ni quand il est porté), vitesse des voitures / motos / bateaux, rafale de coups et kills en masse (les coups au-delà de la limite sont bloqués), **actions à distance** sur un autre joueur (menottes, réanimation, prison, facture… déclenchées sur quelqu'un de trop loin ou sur `-1` : les menus « cuff all / jail all / bill all », liste « Événements ciblés » ESX et QBCore préremplie), 9 nouveaux événements pièges ESX. **Préréglages** Souple / Équilibré / Strict, **couverture des menaces** sur 100 recalculée en direct, **réglage intelligent** (d'après les détections marquées faux positif ou confirmées sur 7 jours : baisser une sanction, monter une limite, passer en kick) et bouton « Protéger les événements exploitables trouvés par le scanner ».
- **Anticheat** (agent FiveM, réglé dans Sécurité > Anticheat) : protection des événements (pièges + anti-spam), contrôle des événements du jeu (entités, explosions, armes données/retirées, éjections, particules, projectiles, dégâts), contrôle des joueurs toutes les 2 s (godmode, vie/armure, super saut, invisibilité, multiplicateurs de dégâts, armes et skins interdits, vitesse, téléportation), module client (heartbeat, ressources injectées, spectate, vision). Chaque détection : désactivée / signalée / kick / ban, avec capture d'écran en option.
- **Captures IA** : `screenshot-basic` + le modèle de vision de `AI_BASE_URL` / `AI_API_KEY` (`AI_VISION_MODEL`, par défaut `meta-llama/llama-4-scout-17b-16e-instruct` sur Groq). Gardées 30 jours. Le ban automatique sur l'avis de l'IA seule est désactivé par défaut.
- **Bans** : sur la license, les comptes liés et les identifiants matériels ; appliqués par l'agent à la connexion (liste gardée en cache sur le serveur FiveM si le panel est injoignable).
- **Carte & vocal** : positions toutes les 2 s, qui parle, radio et appels (pma-voice). Fond de carte : `MAP_IMAGE_URL` (atlas GTA V 8192 px), sinon une grille avec les lieux principaux. Aucun audio n'est capté.
- **Anti-raid Discord** (bot, Sécurité > Anti-raid, désactivé par défaut) : lit le journal d'audit en temps réel ; au-delà de ce qu'une règle tolère, annule tout (rôle recréé et redonné à ses membres, salon recréé, rôles remis, membres débannis, webhooks et bots supprimés…) et sanctionne l'auteur (derank / kick / ban ; rôles rendables depuis le panel). Raids de comptes : verrouillage temporaire. Le bot doit être **Administrateur**, avec son rôle **tout en haut**.
- **Écran en direct** : le staff voit l'écran d'un joueur (≈ 1 image/s via `screenshot-basic`) depuis En direct, la carte ou sa fiche ; le flux s'arrête 15 s après la fermeture, rien n'est stocké. **Geler** un joueur le bloque sur place.
- **Anticheat > Écrans en direct** (permission « Capturer l'écran ») : les joueurs connectés, les plus suspects en premier (détections des 24 dernières heures, faux positifs exclus), l'écran de chacun en fenêtre, ou un **mur de 4 écrans** côte à côte pour surveiller plusieurs suspects ; « Capture » garde une image pour l'analyse IA. Chaque joueur a son propre flux dans l'agent (aucune mise à jour de l'agent nécessaire).
- **Anticheat, en plus** : durée des bans de l'anticheat, cumul de détections (kick puis ban au seuil), alertes vers un webhook Discord, règles de connexion (serveur verrouillé avec liste blanche, Discord/Steam obligatoire, pseudos interdits), journal des connexions refusées, ressource arrêtée chez un seul joueur, détections affichées sur la carte, **comptes liés** (même PC ou même Discord/Steam) sur la fiche joueur.
- **Anti-raid, mode observation** : le bot détecte et signale tout (incidents marqués « observation ») sans rien annuler ni sanctionner, pour lui faire confiance avant de passer en Protection. Un verrouillage manuel reste appliqué.
- **Anti-raid, détections avancées** : raids lents (une vague de comptes créés il y a moins d'une semaine, sans avatar ou aux noms semblables, dès la moitié du seuil en une minute), **comptes piratés** (messages dans 4 salons en 15 s, sans l'intent Message Content), **liens d'arnaque** faux Nitro / faux Steam (domaines sosies : `dlscord`, `steamcomrnunity`, `discord-nitro.ru`… ; les domaines officiels ne sont jamais bloqués) et **raids de messages** (le même message de 4 comptes en 30 s, messages courts ignorés). Ces deux derniers demandent `BOT_MESSAGE_CONTENT=1`.
- **Audit de sécurité Discord** (Anti-raid > Audit Discord, et chaque jour) : le bot lit la configuration du serveur Discord (rôles et permissions, bots Administrateurs vérifiés ou non, permissions de @everyone et des salons, A2F exigée pour la modération, niveau de vérification, webhooks, invitations permanentes, place de son propre rôle) ; le panel note sur 100 (un problème critique plafonne à 35, un haut à 70) et explique chaque correctif. Rien n'est modifié. Les 10 derniers audits sont gardés (`discord_audits`), notés à nouveau à la lecture avec les réglages actuels de l'anti-raid.
- **Anti-raid, en plus** : sanctions quarantaine (rôle dédié) et mute, rôles et salons protégés (toute modification annulée dès la première), permissions de salons modifiées en masse, protection des messages (flood, mentions de masse, @everyone, invitations et liens — ces deux derniers demandent `BOT_MESSAGE_CONTENT=1` et l'intent « Message Content »), alerte en MP au propriétaire, **verrouillage manuel** depuis le panel (vérification max, arrivants expulsés, salons en lecture seule), **sauvegardes** des rôles/salons/rôles des membres (auto toutes les N h + manuelle) et **restauration** après un nuke. Le bot récupère les commandes du panel toutes les 15 s.
- **Anti-raid, personnalisable par serveur** : pour chaque règle, **sa propre sanction** (ou la sanction générale, ou aucune) et **annuler ou non** ; **rôles de confiance** (en plus des personnes) ; **rôle mentionné** dans le salon d'alerte ; **MP à la personne sanctionnée** avec un texte au choix (`{serveur}`, `{sanction}`, `{raison}`) ; raid de comptes : arrivants **expulsés, bannis ou laissés**, salons en lecture seule pendant le verrouillage automatique ; compte trop récent : **expulsé, banni, mis en quarantaine ou seulement signalé** ; messages : sanction des fautes graves (**supprimer seulement, mute, expulser, bannir**), **sites autorisés** quand les liens sont bloqués, **mots interdits** (mots entiers, sans accents ni majuscules ; Message Content). Des réglages enregistrés avant gardent le comportement d'avant. Le bot et le site doivent être mis à jour ensemble.

## Scanner
Sécurité > Scanner : un scan complet du serveur, un rapport avec un **score sur 100** (global et par catégorie), les problèmes classés par gravité (critique, haute, moyenne, info) avec la ressource, le fichier, la ligne, l'explication et le correctif, et l'historique des scores.
- **Sécurité** : backdoors (code téléchargé puis exécuté, noms cachés en `\x..` ou via `_G[...]`, panels connus type cipher-panel, `os.execute` / `io.popen` / `child_process`, `add_ace` / `add_principal` par le code, secrets lus puis envoyés en HTTP, code obfusqué), événements serveur exploitables (montant / objet pris dans les paramètres du client, récompense sans vérification), injections SQL, webhooks et clés lisibles par les joueurs, logique de paiement / permission côté client.
- **Configuration** : `sv_scriptHookAllowed`, ACE données à tout le monde ou `resource.X command`, RCON, `sv_endpointprivacy`, `sv_enforceGameBuild`, artifacts en retard (comparés aux builds recommandés de Cfx.re).
- **Performance** : boucles `Wait(0)` inutiles, requêtes SQL dans des boucles, `GetDistanceBetweenCoords`, fichiers streamés de plus de 16 Mo, assets streamés en double.
- **Maintenance** : `__resource.lua`, `fx_version` obsolète, Lua 5.4 absent, mysql-async / ghmattimysql, natives dépréciées, dépendances manquantes ou arrêtées, ordre des `ensure`, ressources en double, noms d'événements en conflit, ressources sous escrow (signalées « protégées, non analysables »).
- **Comment** : l'agent 3.3+ (`audit.js`, JavaScript serveur) envoie l'inventaire (fichiers, tailles, SHA-256, manifests, `server.cfg` avec tous les secrets masqués) ; le panel demande seulement les fichiers qu'il n'a **jamais** analysés, pour aucun serveur (réputation par hash), vérifie que chaque contenu correspond à son hash, l'analyse avec les règles puis l'oublie. Seuls les résultats et 3 lignes autour de chaque problème sont gardés (30 derniers scans). L'IA ne reçoit que ces 3 lignes, à la demande (« Expliquer et corriger avec l'IA »).
- **Scan continu** (case à cocher) : relancé après un démarrage de ressource et deux fois par jour ; un nouveau problème critique ou haut est envoyé sur le webhook d'alertes de l'anticheat.
- `set fiverax_audit_code 0` : mode confidentiel, aucun code ne quitte le serveur (seuls les fichiers déjà connus sont évalués).

## Studio IA
Trois créateurs (menu « Studio IA », permissions « Studio » et « Déployer »), chacun **à la main** (sans coder) ou **avec l'IA** (on décrit en français, elle écrit la ressource), puis on la télécharge en `.zip` ou on la **déploie** sur le serveur en un clic.
- **UI Creator** : page NUI (HTML/CSS/JS) + `client.lua`. **Mode simple** : un modèle (menu, HUD, compteur de vitesse, formulaire, panneau d'infos) puis des éléments empilés (titre, texte, bouton qui ferme ou lance une commande, jauge vie / armure / vitesse, champ, image), position, couleurs, ouverture (toujours affichée, commande ou touche) ; le panel écrit la page. **Aperçu en direct** en 1920×1080 sur un fond de jeu, dans un cadre isolé : boutons « messages du jeu » (comme `SendNUIMessage`), journal des callbacks NUI et des erreurs JavaScript.
- **Script Creator** : **blocs façon Scratch** (Blockly) : événements (commande, touche, zone, arrivée en jeu, mort, minuterie), actions joueur et véhicule, argent (ESX / QBCore / Qbox), annonces, conditions, boucles. Les commandes tournent côté serveur (droits vérifiés, argent donné par le serveur), le reste côté client ; un bloc mal placé est signalé. Ou l'IA : `fxmanifest`, `config`, client, serveur, README pour Standalone / ESX / QBCore / Qbox, le serveur ne faisant jamais confiance au client.
- **Mapping Creator** : éditeur vue de dessus (glisser, tourner, dupliquer), **catalogue de props et kits prêts à poser** (barrage de police, stand, terrasse, barbecue, chantier) à glisser sur la carte, centre posé sur un lieu ou **la position d'un joueur en jeu** ; l'IA compose ou modifie la scène. Le panel écrit lui-même le `client.lua` (objets figés qui apparaissent quand un joueur approche).
- **Blocs / mode simple ↔ code** : les fichiers d'une création visuelle sont générés (lecture seule) ; « Code » les rend modifiables à la main, et une demande à l'IA fait passer la création en code (les blocs restent dans l'historique).
- **Vérifications** à chaque modification : fichiers déclarés absents, blocs Lua non fermés, appels dangereux (`os.execute`…), événements réseau qui donnent de l'argent ou des objets sans contrôle ; bouton « Corriger avec l'IA ».
- **Versions** : chaque demande à l'IA, modification ou restauration est gardée (40 dernières) et restaurable.
- **Déploiement** : l'agent (3.2) écrit la ressource dans `resources/[fiverax_studio]/<nom>` (à côté de son propre dossier), fait `refresh` puis la (re)démarre. Il ne touche jamais une ressource du même nom hors de ce dossier. `set fiverax_deploy 0` le refuse. Modèle IA : `AI_CODE_MODEL` (sinon `AI_MODEL`), longueur de réponse `AI_CODE_MAX_TOKENS` (8000).

## Assistant IA
Page « Serveur FiveM > Assistant IA » (permission « Console du serveur et assistant IA »). On décrit un problème en jeu (ressource qui ne démarre pas, erreur de script, job cassé…) ; l'IA lit la console (erreurs en priorité), l'état des ressources et le dernier scan, explique la cause et propose des actions en un clic (commande console, démarrer / redémarrer une ressource, toujours après confirmation).
- **Gestion en jeu** : on parle naturellement (« rembourse 5000 $ à Tata », « mets Bob mécano grade 2 », « réanime Lucas », « téléporte Tata sur Bob », « combien a Bob en banque ? »). L'IA retrouve le joueur parmi les connectés et propose les actions : argent (liquide, banque, argent sale), objets, job, réanimer, soigner, téléporter, infos du joueur (permission « Gérer les joueurs en jeu »), message privé, gel, kick, annonce (leurs permissions habituelles). Chaque action est confirmée (« Tout exécuter » pour plusieurs), son résultat revient dans la conversation et dans les logs. L'agent 3.6 (`game.lua`) détecte ESX, QBCore ou Qbox et ox_inventory ; seulement les joueurs connectés. `set fiverax_game 0` refuse ces actions.
- **Fichiers** (permission « Laisser l'assistant IA lire et modifier les fichiers des ressources ») : l'IA demande à lire la liste des fichiers d'une ressource ou certains fichiers ; l'agent 3.5 (`files.js`) les envoie et l'IA continue avec leur contenu. Elle propose ensuite une modification (remplacements précis ou fichier complet) affichée en **diff** : « Appliquer et redémarrer », « Appliquer sans redémarrer » ou « Ignorer ».
- **Sécurité** : seulement des fichiers texte (`.lua`, `.js`, `.json`, `.html`, `.css`, `.cfg`, `.sql`…) dans le dossier de la ressource (pas de `..`), jamais `fiverax_agent`. Avant d'écrire, l'agent vérifie que chaque fichier est encore celui que l'IA a lu (SHA-256) : sinon rien n'est écrit. Il garde une copie `<fichier>.fiverax.bak`. Chaque lecture et écriture est dans les logs.
- **Annuler** : chaque modification appliquée garde le contenu d'avant et s'annule en un clic (historique en bas de la page).
- `set fiverax_files 1` : l'IA peut lire mais pas modifier ; `set fiverax_files 0` : ni l'un ni l'autre.

## Reports & boîte noire
Page « Serveur FiveM > Reports & replays » (permission « Traiter les reports des joueurs et revoir les incidents »). Agent **3.7** (`blackbox.lua`).
- **Boîte noire** : l'agent garde en mémoire les dernières minutes du serveur (`set fiverax_blackbox_seconds 300`, 60 à 900) : position, cap, vie, armure, véhicule, qui parle, radio et appel de chaque joueur toutes les 2 s, plus les coups et les morts entre joueurs (tueur et arme, signalés par le client de la victime), connexions, déconnexions et détections. Rien ne part tant qu'il n'y a pas d'incident. Aucun son.
- **`/report [id] raison`** en jeu (nom de la commande : `set fiverax_report_command`, `""` pour aucune ; les scripts de report existants peuvent appeler `exports.fiverax_agent:report(source, cible, raison)`). 10 s plus tard, l'agent envoie la fenêtre au panel, limitée aux joueurs passés à moins de 300 m des personnes concernées. Le staff en jeu (`add_ace group.admin fiverax.staff allow`) est prévenu dans le chat, et le webhook d'alertes de l'anticheat reçoit le report. Un report toutes les 2 min par joueur.
- **Captures** : « Capturer maintenant » (autour d'un joueur ou de tout le serveur) et, automatiquement, chaque kick ou ban de l'anticheat (3 dernières minutes).
- **Replay** : carte avec lecture, vitesse ×1 à ×8, trajets, tirs (traits), morts (croix), détections, qui parle ; chronologie cliquable (tirs regroupés, armes nommées) ; distances entre les personnes concernées. Prise en charge, clôture avec une décision et une réponse au joueur, ban direct du signalé.
- Les replays sont gardés 30 jours (gzip), les reports restent. `set fiverax_blackbox 0` désactive la boîte noire et `/report`.

## Espace joueur
`/joueur` : un joueur se connecte avec Discord et voit, sur chaque serveur où son Discord est relié à FiveM, son temps de jeu, ses sessions, ses bans (raison, durée), ses `/report` et la réponse du staff, ses votes et leurs récompenses. Jamais ses identifiants, son IP, les détections ni les notes du staff.
- **Contester un ban** : une contestation à la fois par ban, 7 jours d'attente après un refus. Le staff la traite dans Reports & replays > Contestations de ban (permission « Bannir ») : accepter lève le ban, la réponse est lue par le joueur. Le webhook d'alertes reçoit chaque contestation.

## Portail joueurs du serveur
Réseau Fiverax > Portail joueurs (permission « Gérer le portail joueurs ») : chaque serveur construit sa page `/joueur/<adresse>` avec des blocs, avec un aperçu en direct, un brouillon puis une publication (`?preview=1` montre le brouillon à son staff). Titre, accroche, logo, bannière et couleur de la page ; blocs ajoutables, réordonnables, masquables et duplicables (40 maximum).
- **Blocs** : en-tête, annonce (info, important, événement, mise à jour), événement avec compte à rebours, boutons (Discord, boutique, `cfx.re/join`, `fivem://connect`…), texte, FAQ, règlement, statut du serveur en direct avec bouton Rejoindre, **mes stats** (temps de jeu, sessions, en jeu, ban actif du joueur connecté), **formulaire** et **giveaway**. Les liens doivent être en https (ou `fivem://connect`, `cfx.re`, `discord.gg`) ; tout le reste est retiré.
- **Formulaires** (candidature staff, whitelist, suggestion…) : questions courtes, paragraphes, choix, nombres, oui/non, obligatoires ou non ; connexion Discord, heures de jeu minimum, une seule réponse par joueur (sinon une toutes les 10 min et 3 en attente maximum), ouvert ou fermé. Onglet **Réponses** : accepter, refuser, marquer comme lue, avec un message que le joueur lit sur le portail (temps de jeu du joueur affiché au staff).
- **Giveaways** : lot, image, fin des inscriptions, nombre de gagnants, heures de jeu minimum. Les joueurs s'inscrivent ou se retirent ; le tirage (aléatoire, une seule fois) se fait automatiquement à la date de fin (`tick`) ou depuis l'onglet **Giveaways**. Récompense en jeu facultative (argent ou objet), donnée par l'agent au gagnant une minute après sa connexion, comme les récompenses de vote (5 tentatives, 7 jours d'attente au maximum).
- L'espace joueur `/joueur` et la fiche annuaire mènent au portail publié du serveur.

## Annuaire public
`/annuaire` liste les serveurs qui utilisent Fiverax : c'est une vitrine pour eux et un canal d'acquisition pour Fiverax (appels « Référencer mon serveur » sur chaque page, comptés).
- **Fiche** (menu Réseau Fiverax > Fiche annuaire, permission « Gérer la fiche du serveur dans l'annuaire public ») : nom, adresse `/annuaire/<slug>`, accroche, présentation, logo, bannière, galerie, connexion FiveM (`cfx.re/join/…` ou `ip:port`), Discord, site, étiquettes, framework, langue, âge minimum. Aperçu avant publication ; publiable dès qu'il y a une accroche, une présentation et une connexion ou un Discord.
- **En direct** : joueurs connectés (agent), joueurs différents sur 7 jours ; masquable.
- **Avis vérifiés** : connexion Discord, au moins 1 h de jeu sur le serveur d'après les sessions de l'agent (compte Discord lié en jeu), jamais par le staff du serveur. Un avis par compte (modifiable), réponse publique du serveur. 3 signalements de comptes différents masquent l'avis jusqu'à la modération des admins de la plateforme (même page).
- **Mise en avant** : créneaux « À la une » posés par les admins de la plateforme (`PANEL_OWNER_IDS`) pour l'instant ; le paiement viendra plus tard (`directory_featured.source`).
- **Votes** : un vote par compte Discord et par serveur toutes les 2 h (la même règle pour tous, pour un classement juste), comptes Discord de plus de 30 jours, une seule adresse réseau par fenêtre (gardée hachée). Les votes du mois classent l'annuaire (« Top votes ») et comptent dans la pertinence.
- **Récompenses de vote** (Fiche annuaire > Récompenses de vote) : jusqu'à 3 lignes argent (liquide, banque, argent sale) ou objets, données en jeu par l'agent 3.7 au joueur dont le Discord est relié à FiveM, une minute après sa connexion s'il n'était pas en jeu (attente maximale 7 jours). Un échec avant tout don est retenté (5 fois), un don n'est jamais refait.
- **Statistiques** (30 jours) : vues de la fiche, clics Rejoindre, Discord, boutique, site. Données structurées (note moyenne) et `sitemap.xml` pour le référencement.

## Scan gratuit, badge « Protégé par Fiverax » et parrainage
Trois boucles d'acquisition qui s'alimentent : le scan amène des propriétaires, le badge affiché sur leurs sites en amène d'autres, et chaque lien porte le parrainage du serveur.
- **Scan gratuit** (`/scan`, sans compte) : on colle un lien `cfx.re/join/…` ou une adresse `ip:port`. Le panel lit seulement ce qui est public (liste officielle Cfx.re, `info.json`, `players.json`, `dynamic.json`), passe **18 vérifications** et donne une **note de A+ à F** (score sur 100) : ScriptHook, `sv_pureLevel`, OneSync (et OneSync Legacy), build du jeu, artifacts en retard ou avec faille, **IP des joueurs publiques**, **identifiants des joueurs publics** (`sv_exposePlayerIdentifiersInHttpEndpoint`), anticheat visible, **ressources ciblées par les menus de triche** (anciennes ressources ESX / vRP aux événements de paie, prison ou admin exploitables), **ressources « leak / nulled / cracked »**, `runcode`, `mysql-async` / EssentialMode, deux frameworks ou deux librairies SQL ensemble, nombre de ressources.
  - Rapport v2 : checklist complète (réussi, échec, non visible de l'extérieur, réservé au scan complet), « **Ce que n'importe qui voit de ton serveur** » (joueurs dont l'IP ou les comptes sont lisibles, ressources listées et ciblées, versions), **percentile** (« mieux que N % des serveurs scannés ces 30 jours », dernier scan de chaque serveur, à partir de 20 serveurs), **évolution** depuis le scan précédent du même serveur, **image de partage** générée (note, score, problèmes graves) pour Discord et les réseaux.
  - Les étapes du scan sont **affichées en direct** (`/api/scan` en `application/x-ndjson`). Connecté, on peut relancer le scan d'un serveur une minute après le précédent pour vérifier une correction (sinon 10 min de cache).
  - Sans compte : le score et les titres ; après connexion Discord : détail, correctif, plan d'action, bloc `server.cfg` et ressources du kit en `.zip`. Rapport à `/scan/<jeton>` (non indexé), gardé 30 jours. Les anciens rapports restent lisibles.
  - Sécurité : une adresse est résolue une fois et **toutes** ses IP doivent être publiques (privées, locales, CGNAT, documentation, IPv4 dans IPv6 refusées), la requête part vers cette IP (pas de rebinding DNS), ports < 1024 refusés, GET sur trois chemins fixes, aucune redirection suivie, 4 s et 1,5 Mo maximum. 8 scans par heure et par adresse réseau (gardée hachée), le même serveur n'est pas relu avant 10 min. Les joueurs sont comptés, jamais gardés (ni nom, ni IP, ni identifiant).
- **Protection & badge** (Sécurité > Protection & badge, permission « Voir l'anticheat… ») : un niveau calculé uniquement à partir de ce que Fiverax vérifie lui-même.
  - **Protégé** : agent connecté cette semaine, scan complet de moins de 30 jours sans problème critique, anticheat actif. **Renforcé** : + score ≥ 80, aucun problème haut, anti-raid Discord, webhook d'alertes. **Forteresse** : + score ≥ 92, scan continu, scan de moins de 7 jours, bans partagés. Chaque niveau exige ceux du dessous ; la checklist mène à la page qui corrige.
  - **Plan d'action** : construit par les règles (problèmes du dernier scan, du plus grave au plus fréquent, puis vérifications manquantes) ; « Personnaliser avec l'IA » le réécrit (l'IA ne reçoit que les règles, les comptes et les noms de ressources, jamais de code), gardé jusqu'au scan suivant.
  - **Kit de protection** (ressources serveur écrites à la main, sans dépendance, qui passent le scanner) : `fvx_event_guard` (délai, appels par minute, distance, montant valide, à appeler au début des événements), `fvx_webhooks` (webhooks rangés dans des convars, relais limité pour les scripts client, jamais de mention), `fvx_join_guard` (anti-flood de connexion par adresse et global, pseudos contenant du HTML refusés). « Installer sur le serveur » les copie dans le Studio et les déploie (permissions Studio et Déployer) ; aussi en `.zip`. Plus le bloc `server.cfg` qui corrige les problèmes de configuration.
  - **Badge public** (désactivé par défaut, permission « Régler l'anticheat… ») : image `/badge/<id>.svg` (`?style=flat` : 20 px), page de vérification `/protection/<id>` qui ne montre que le niveau, le score, la date et les protections en place (jamais les problèmes), codes à coller (HTML, Markdown, BBCode, Discord). Les fiches annuaire affichent le niveau, le filtre « Protégés » et un bonus de classement (8 / 12 / 16).
- **Parrainage** (Réseau Fiverax > Parrainage, propriétaires) : lien `/r/<code>` (cookie 30 jours ; `?to=scan` ouvre le scan). La page de vérification du badge et la fiche annuaire portent le lien du serveur. Un serveur ajouté après ce lien devient filleul (pas soi-même, pas un serveur du même créateur ou d'un propriétaire du parrain, un seul parrain). Il est **validé** quand son agent s'est connecté et que 5 joueurs différents y ont joué, dans les 60 jours (vérifié par le `tick`) : **7 jours « À la une »** pour le parrain, 3 pour le filleul, +7 au 3ᵉ parrainage (titre « Ambassadeur » sur la fiche) et +30 au 10ᵉ. Les jours se dépensent en créneaux « À la une » (`directory_featured.source = 'referral'`), fiche publiée requise.

## Qui voit quoi
- **N'importe qui** se connecte avec Discord et **ajoute son serveur** : seulement un serveur Discord où il est propriétaire, administrateur ou a « Gérer le serveur » (limite `MAX_SERVERS_PER_USER`, 5 par défaut). Il en devient propriétaire et la page Configuration le guide (bot, rôles, équipe, FiveM). **Pendant la bêta privée**, seuls les partenaires choisis dans `/admin` le peuvent ; les autres demandent l'accès (voir Administration).
- **Administrateurs de la plateforme** (`PANEL_OWNER_IDS` dans `site/.env`, facultatif) : tous les serveurs, tous les droits, sans limite, ajout manuel de n'importe quel serveur Discord, et le panel d'administration `/admin`.
- **Propriétaires d'un serveur** (le créateur, puis ceux qu'il ajoute) : tous les droits sur ce serveur, ses pages « Configuration » et « Accès & rôles », et peuvent le supprimer (avec toutes ses données).
- **Accès & permissions** (personnes ou rôles Discord) : définis séparément pour chaque serveur.

## Administration de la plateforme (`/admin`)
Réservée à `PANEL_OWNER_IDS` (lien « Administration » dans la barre latérale ; tout autre compte reçoit une 404). Chaque action est écrite dans le **journal** de l'administration, et celles qui touchent un serveur aussi dans ses propres logs.
- **Vue d'ensemble** : comptes (nouveaux, actifs 24 h, bannis), serveurs (nouveaux, suspendus), agents FiveM en ligne, bot, appels IA du jour et refus des quotas, scans gratuits, alertes de configuration et file de modération.
- **Serveurs** : recherche et filtres (agent en ligne, jamais relié, suspendus). Fiche : propriétaires (ajout / retrait, le dernier reste), usage IA, logs. **Suspendre** (raison montrée aux propriétaires) : panel fermé, agent FiveM refusé, le bot cesse de surveiller et d'agir (anti-raid compris, actions en attente retenues), pages publiques masquées (annuaire, portail, boutique, badge), bans retirés du réseau. Rien n'est supprimé ; **Rétablir** remet tout. **Supprimer** demande de taper l'identifiant du serveur (jamais le serveur `default`).
- **Comptes** : chaque compte qui s'est connecté (`platform_users`). **Bannir** (aussi un ID qui ne s'est jamais connecté) : connexion refusée et sessions fermées dans les secondes ; ses serveurs continuent (à suspendre à part). Sessions de chaque compte (appareil, activité) : en fermer une, ou toutes.
- **Bêta & partenaires** : la **bêta privée** est active par défaut (Réglages). Pendant la bêta, seuls les **partenaires** (comptes choisis ici, ou en acceptant une **demande d'accès**) ajoutent un serveur, et un serveur ne s'ouvre que si un de ses propriétaires ou son créateur est partenaire (son équipe y accède alors normalement ; le serveur `default` reste ouvert). Les autres comptes voient « Bêta privée » sur leur liste de serveurs avec un formulaire de demande (nom, lien, joueurs, message ; refusée : nouvelle demande après 7 jours). Pages joueurs, annuaire, scan, bot et agents ne sont jamais bloqués. Retirer un partenaire ferme ses serveurs sans rien supprimer.
- **Retours** : chaque page du panel a **Signaler un bug** (en bas du menu) : bug, idée ou question, envoyé avec la page et le serveur. À traiter ici (vu, traité avec une note).
- **Modération** : avis de l'annuaire et créations de la bibliothèque masqués après signalements, à republier ou retirer (centralisé ici au lieu d'être réparti dans les pages des serveurs).
- **Réglages** (`platform_settings`, effet en ~10 s sur toutes les instances) : inscriptions ouvertes ou fermées, serveurs par compte (remplace `MAX_SERVERS_PER_USER`), scan gratuit, **annonce** en haut de toutes les pages du panel, **maintenance** (seuls les administrateurs entrent ; bot, agents et pages publiques continuent), **IA** activée et **quotas** par serveur, par compte et global par jour (0 = sans limite).
- **Système** : variables manquantes ou trop faibles (jamais leur valeur), redirection Discord, base joignable, migrations. `/api/health` ne répond plus que `{ok}` aux visiteurs (200/503 pour les moniteurs) ; le détail est réservé aux administrateurs.

## Sécurité du site
- **Sessions côté serveur** (`auth_sessions`) : le cookie reste signé (HMAC), et son identifiant doit exister en base, ni fermé ni expiré, compte non banni. La déconnexion ferme vraiment la session (un cookie copié ne marche plus). À la mise en production de cette version, **tout le monde doit se reconnecter une fois**.
- **Connexion Discord** : l'état OAuth est lié au navigateur (cookie) en plus d'être à usage unique en base : impossible de connecter quelqu'un au compte d'un autre avec un lien de callback. 30 démarrages de connexion / 10 min par adresse.
- **CSRF** : en plus des cookies `SameSite=Lax`, `src/middleware.ts` refuse toute requête d'écriture vers `/api` venant d'un autre site (`Sec-Fetch-Site`, `Origin`). Non concernés : `/api/bot`, `/api/fivem`, `/api/tebex/webhook` (jeton ou signature).
- **En-têtes** : `X-Frame-Options: DENY` (pas de clickjacking sur les boutons ban / suppression / déploiement), CSP `base-uri 'self'; object-src 'none'; form-action 'self'`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, HSTS, `nosniff`.
- **Quotas IA** (`ai_usage`) : chaque appel (studio, assistant, Store Creator, plans, explications, bilans, captures) est compté avant de partir, par serveur et par compte ; au-delà, « quota atteint » sans appel. Les captures envoyées par un agent ne comptent que pour son serveur. Sans eux, n'importe qui (l'inscription est libre) pouvait épuiser la clé IA de toute la plateforme.
- **Limites d'abus** (`rate_limits`, partagées entre instances) : création de serveurs (10 / h / compte), actions annuaire et portail (30 / 10 min / compte), statistiques de l'annuaire comptées une fois par visiteur, fiche et heure.
- **Bans partagés** : le blocage compte les **personnes** qui ont créé les serveurs, plus les serveurs : multiplier ses propres serveurs ne permet plus de faire bloquer un joueur partout. Les bans d'un serveur suspendu ne comptent plus.
- **Adresse des visiteurs** : lue partout de la même façon (`x-real-ip`, puis le premier `x-forwarded-for`) et seulement gardée hachée.
- Nettoyage par le `tick` : sessions finies depuis 30 jours, fenêtres de limites, usage IA de plus de 120 jours.

## Migration depuis la version mono-serveur
Automatique au premier démarrage (migration `013_multi_server`) : toutes les données existantes passent dans le serveur `default`, relié au `DISCORD_GUILD_ID` de l'ancien `.env`. L'ancien `FIVEM_AGENT_TOKEN`, `GRADE_ROLE_MAPPING_JSON` et `DISCORD_STAFF_ROLE_IDS` continuent de fonctionner, **pour ce serveur uniquement**.
Le site et le bot doivent être mis à jour **ensemble** (le format des messages du bot a changé).

## Bot Discord personnalisable
- **Par serveur** (Administration > Bot Discord, propriétaires) : le bot partagé prend le **nom, l'avatar, la bannière et la bio** du serveur, **sur son Discord seulement** (Discord « Modify Current Member » : `PATCH /guilds/{id}/members/@me`). Aperçu du profil avant d'enregistrer, images recadrées dans le navigateur (avatar 512 × 512, bannière 1020 × 360, GIF animés gardés tels quels, 1,5 Mo), « Rétablir le bot d'origine ». Appliqué tout de suite par le site avec `DISCORD_BOT_TOKEN` ; dernier état dans `bot_profiles`, chaque changement dans les logs du serveur ; 10 changements par heure et par serveur.
- **Partout** (`/admin/bot`, administrateurs) : nom d'utilisateur (2 changements par heure, règle de Discord), avatar, bannière et « À propos de moi » du bot (`PATCH /users/@me`, `PATCH /applications/@me`), et son **statut** (en ligne, inactif, ne pas déranger, invisible) avec une **activité** (joue à, regarde, écoute, participe à, statut personnalisé ; `{serveurs}` = nombre de serveurs protégés). Le statut part avec chaque signal de vie : le bot l'applique en 30 s.

## Tutoriels (`/guides`)
Guides publics pas à pas (indexés, liés depuis le menu « Aide > Tutoriels » du panel, l'en-tête des pages publiques, la liste de mise en route et un lien « Tutoriel » dans l'en-tête des pages concernées) : démarrer, installer l'agent FiveM, anticheat, anti-raid, boutique Tebex, staff, scanner et badge, annuaire / portail / votes, Studio IA et assistant, reports et boîte noire, dépannage. Le contenu est dans `site/src/app/guides/content.tsx` : à tenir à jour avec les fonctionnalités.

## Agent FiveM téléchargeable
Le panel distribue l'agent : Configuration > Agent FiveM > **Télécharger l'agent** (`/api/agent/download`, compte connecté), un `.zip` avec le dossier `fiverax_agent` et un `LISEZMOI.txt` (lignes du `server.cfg` pré-remplies avec l'adresse du site, options). Le site étant déployé seul, l'agent y est **copié** : après chaque modification de `fivem/fiverax_agent`, lancer `npm run embed-agent` dans `site/` (un test échoue tant que la copie n'est pas à jour). La page Configuration signale aussi un agent **plus ancien** que celui distribué.

## Mise en route locale
```bash
cd site && npm install && npm run dev      # http://localhost:3000
cd bot  && npm install && npm start        # dans un second terminal
```
Voir `site/README.md` et `bot/README.md` pour la configuration détaillée.

## Si le site est arrêté
Le bot réessaie (3 tentatives par message). Les événements vocaux perdus sont rattrapés par la synchronisation complète suivante (au maximum 30 min d'écart), et au redémarrage du bot tout est resynchronisé.
